# 订阅功能配置指南

核查日期：2026-11-04。Brevo 表单、域名认证与中文确认页面已经配置。测试邮箱已收到双重确认邮件，作者反馈点击确认成功；单人测试文章通知已送达，作者点击邮件内链接后退订成功，Brevo 后台显示该邮箱的 Email campaigns 为 Blocklisted。核心流程通过，邮件订阅入口已开放。

## 当前方案

- Astro 7.1.6 静态输出；`wrangler.jsonc` 指向 Cloudflare 静态资源目录 `dist`，不需要服务器或数据库。
- `/subscribe/` 复用全站布局与样式；导航、所有文章末尾有入口。
- 中文 `/zh/rss.xml` 与英文 `/en/rss.xml` 保持原实现。英文内容目前为空，因此英文源可能没有文章。
- 微信名称按作者提供的「为何是他」，ID 为 `ReasonForHim`。没有真实二维码，暂不展示二维码。
- 邮件采用 Brevo 官方 iframe，无 API Key，不由本站接收或存储邮箱。中文的提交后页面和确认成功页面分别为 `/subscribe/check-email/` 与 `/subscribe/confirmed/`。
- 不加载 OneSignal、不注册推送 Service Worker，也不显示尚未验收的通知按钮。

## 免费方案评估

Brevo 免费版每日 300 封邮件，适合初期手动发送；确认邮件也要为发送额度留余量。上千名微信关注者不等于邮件订阅者，不导入或推定其邮件同意。若未来有 1,000 名邮件订阅者，单次全量通知至少跨 4 天，不能承诺当天送达；按已确认订阅者分组发送，记录已发组别，避免重复发送。额度用尽时不要默认服务会自动补发。

MailerLite 当前免费版为 250 名活跃订阅者、每月 2,500 封，超过订阅者上限会限制发送；对于长期扩展，本次优先 Brevo。免费额度可能调整，上线前以账户实际显示为准。

来源：[Brevo 免费限制](https://help.brevo.com/hc/en-us/articles/208580669)、[MailerLite 免费计划](https://www.mailerlite.com/free-plan)、[MailerLite 额度变化](https://www.mailerlite.com/help/free-plan-update-faq)。

## 作者需要完成或授权的步骤

1. 注册或登录 Brevo 免费账户，完成服务商审核。不要把密码、API Key 发到聊天或写进代码。本方案不需要 API Key。
2. 添加真实发件人邮箱（应能接收回复）。在域名认证页面取得针对自己域名的记录；先审查现有 DNS，再按页面给出的实际值设置 Brevo 验证记录、DKIM、DMARC。涉及 DNS 变更先由作者确认。
3. Brevo 标准共享发送路径并不要求额外 SPF/MX 来认证域名，不能照抄网上的通用 SPF。保留现有邮件服务的 SPF、MX；若实际配置要求调整 SPF，在原有唯一 SPF 记录中合并，不能新增第二条 SPF。已有 DMARC 不重复新增，也不盲目降低现有策略。DKIM CNAME 如经 Cloudflare 管理，应按服务商要求使用 DNS-only。
4. 在 Brevo 创建独立文章订阅列表及订阅表单，只收集必要的邮箱；加入清晰、非默认勾选的同意说明。开启 **Double confirmation / 双重确认**，选择确认邮件模板，配置提交后提示和确认后的成功提示。不要使用单次确认替代。
5. 表单采用简洁中文、墨绿 `#25483f` 和米白配色。按服务商防滥用建议配置保护，并用大陆普通网络测试表单、验证码和确认邮件。若验证码无法使用，不应简单关闭保护后上线。
6. 在每封新文章通知中使用 Brevo 自带的退订链接、真实发件人信息及平台要求的页脚。以简短摘要加原文链接手动发送，第一封先发给经授权的测试邮箱。
7. 从表单分享页面复制 **iframe 的 src 地址**，交给维护者即可，不需要整段脚本或密钥。维护者填入 `src/config/subscriptions.ts` 的 `formUrl`。仅接受 HTTPS、Brevo 的 `.sibforms.com` 域名与 `/serve/` 或 `/v2/serve/` 路径；若官方地址格式变化，应核实后调整校验。
8. 先通过 Brevo 托管表单完成下述真实测试，再在本地将 `verified` 改为 `true` 预览嵌入表单；对桌面及手机检查内部滚动、验证码、提交成功提示与确认流程。iframe 是跨域内容，本站不能直接读取其提交结果，也不会伪造成功提示；高度目前 650px，按真实表单调整。
9. 完成验收、作者确认发布后，再提交本次相关文件并部署。仅填 URL 不会开启邮件入口，必须同时通过验收开关。变更设置后要重新构建。

官方说明：[创建表单及双重确认](https://help.brevo.com/hc/en-us/articles/208771869-Create-a-sign-up-form-in-Brevo)、[域名认证与 SPF 说明](https://help.brevo.com/hc/en-us/articles/12163873383186-Authenticate-your-domain-with-Brevo-Brevo-code-DKIM-DMARC)。

## 邮件真实验收（核心流程通过）

使用作者授权的测试邮箱，建议覆盖 QQ/163 和 Gmail/Outlook，并记录时间及结果；不把邮箱原文写入仓库。

2026-11-04 已完成 Gmail 测试：托管表单提交、收到并点击双重确认邮件、单人测试文章通知送达、邮件内链接退订、后台 Email campaigns 标记为 Blocklisted。尚未覆盖下面的所有边界情形与地区网络，后续可继续补测。

- 提交无效地址被拒绝，合法地址显示正确提示；同意选项不能被跳过。
- 提交后收到确认邮件；未点击确认前不能进入可群发名单。
- 点击确认后在 Brevo 看见已确认订阅，重复确认或重复订阅不会导致重复发送。
- 确认后没有收到第二封邮件并不说明双重确认失败：Brevo 的最终确认邮件是可选设置。退订应在文章通知邮件中验证。
- 发一封测试文章通知，验证标题、原文链接、回复地址、垃圾箱情况，以及邮件头的 SPF、DKIM、DMARC 结果与域名对齐。
- 从邮件内退订，确认平台不再向该地址发送文章通知；再选测试收件组验证退订地址被排除。
- 大陆正常网络访问表单及收取邮件；同时测试嵌入版与独立表单链接。失败时保留 RSS/微信，不宣称已开通。

## Web Push 评估及以后启用的条件

OneSignal 免费 Web Push 为每次最多 10,000 名订阅者。Cloudflare 静态托管可以提供 HTTPS 和根目录 Service Worker，技术上兼容；当前不需要后端或 REST API Key。

但大陆浏览器推送服务、SDK 与网络可达性并未实测，不能保证 Android Chrome 等浏览器依赖的通道持续可达；微信内置浏览器也不能视为支持。当前决定暂缓，不把未知条件包装成可用功能。

iOS/iPadOS 16.4+ 需从主屏幕 Web App 打开，再由读者点击按钮授权，普通 Safari 标签页不能直接完成。未来应提供 manifest、适配图标与添加主屏幕说明，兼容较早支持版本。桌面 Safari、Chrome、Edge、Firefox 和 Android 支持浏览器仍需分别测试，不能由桌面成功推断手机成功。

未来作者授权创建 OneSignal 应用后：用真实公开 App ID，固定正式 origin；安装官方 SDK/Worker，检查既有 Worker 冲突；禁用自动弹窗、自动提示及浮动订阅铃。仅点击「接收新文章通知」时请求权限。处理拒绝、不支持、离线及加载失败，提供取消订阅入口，不反复请求。不得将 REST API Key 放入前端。

启用前必须在获准的 HTTPS 测试环境逐项完成：订阅→后台发送→设备收到→点击打开对应文章→取消订阅；覆盖大陆与海外网络、iOS 主屏幕、Android、桌面浏览器。未通过时不显示入口，不加载 SDK。生产域名和测试域名的订阅相互独立，正式发布后还需经授权的生产冒烟测试。

来源：[OneSignal 价格](https://onesignal.com/pricing/)、[Web Push 要求](https://documentation.onesignal.com/docs/en/web-push-setup)、[iOS 限制](https://documentation.onesignal.com/docs/en/web-push-for-ios)。

## 部署与回退

本地预览构建：`npm run build -- --outDir output/subscriptions-preview`。正式构建继续使用原来的 `npm run build`，输出 `dist`；不要误把临时预览目录作为生产资源目录。

如果托管环境将来设置 CSP，启用表单时需把实际表单 origin 加入 `frame-src`，不要使用通配符放宽整个策略。跨域表单加载失败时保留新窗口链接及 RSS/微信。真实表单需补充核对其隐私说明和平台管理的订阅数据删除流程。

邮件异常时将 `verified` 设回 `false` 并重新构建部署，页面回到未开放状态；这只隐藏入口，已有订阅者和退订状态仍在 Brevo。勿以回退页面代替退订。全部功能上线和付费升级均需作者明确确认。
